# P5 预算计划、延期与复习

依据总纲3.4、P5。沿用Vue/Spring/MyBatis/PostgreSQL单体、用户行锁和事务审计，无新依赖、模型调用或生产部署。GraphFlow工具未提供，定向本地检查，不声称context/plan/index执行。

## 分步验收

1. **预算与计划草案**：11408、Java、Blender三技能，按目标优先级/截止日期/先修完成/近期结果/到期复习排序；总预算和每技能上限均不能超，任务按整项选择，所有取舍有原因。生成/编辑草案不触碰任务或当天正式计划。
2. **确认与调整**：revision、源指纹、明确确认与幂等键；陈旧草案409；确认事务追加不可变计划版本并切换当天指针，不改任务截止日期/标题/状态。取消计划保留历史。任务顺延、拆分、取消保留旧任务和调整原因；拆分分钟之和不变，进行中的计时须先结束。
3. **复习闭环**：手动首复习日期或已确认节点证据安排，IANA时区转换UTC；队列、暂停/恢复、调期、复测结果和调度历史可查。复测必须有同节点的新作答/已确认新证据，不能重复旧结果刷间隔；正确/提示后正确/错误/不确定有不同且可解释的保守规则，不改能力评估。
4. **持久化与安全**：无Key闭环；所有权/复合FK、并发与幂等、故障回滚；真实PG、桌面/手机、Docker网关；日志和学习样例不提交Git。P6不提前开始。

## 设计

计划日期为用户选择的日历date，时区必须同时被Java ZoneId及PostgreSQL时区库识别。预算指确认时的预计分钟，不是对实际计时的强制中断。每天一个当前计划指针；历史计划/条目/技能上限不可改，替换必须重新确认。不用任务due_date保存计划日期，避免覆盖真实截止日期。

候选任务不包含已完成/取消、归档技能节点、非进行中目标；DEFERRED在新截止日期前不参与。先修完成依据已有DONE任务或路线自报完成，不等于能力已验证，也不把“计划先修”当成“已经完成”。到期复习先于学习；同类内按进行中、目标优先级、最早截止、近期错误/不确定及稳定ID排序，再逐轮跨技能选择，避免同一技能占满全部可用时间。超出总预算/技能预算、先修未完成或候选上限等原因均显示，不自动拆分或伪造用时。

草案为关系表，保存候选快照与取舍；编辑只改变选择及顺序。确认重新计算源指纹/约束，追加正式快照后切换当前指针。未来当前计划中的任务禁止直接修改预计分钟，需先取消当天计划，再调整并重新确认，避免绕过预算。完成/延期不会重写旧计划快照，页面同时展示现状。支持手动替换/取消当天计划，所有历史可追溯。

复习调度按稳定节点每用户一条，保留原任务/技能；明确安排，不凭一次答对自动创建。初次证据正确3天，其余1天；手动可选首日期。独立且规则比对正确的复测间隔翻倍，最多365天；提示后/自评正确、错误、不确定均回到1天，原因记录来源和独立性，用户可手动调期。规则v1不是经过个体校准的记忆模型，不承诺最优复习时间。

每复习周期仅一个关联任务，草案阶段不创建，确认时才创建/复用；跨日重新安排复用未结束的同周期任务，不复制积压。复测确认后结束该周期任务，保留原任务/作答/证据；活动计时须用户先结束。新周期建立新关联，旧记录不删除。复测事件及计划/调整历史追加。

计划由确定性规则真实生成，UI明确标记规则来源，不假称AI建议。本轮不自动请求模型；可选AI文字增强未接入，不能绕过规则或冒充实现。

## 接口与页面

`/api/v1/planner`：drafts生成/详情/列表/修改/确认、days当前/版本/取消、tasks延期/拆分/取消/调整历史。
`/api/v1/reviews`：schedules创建/列表/调期/暂停恢复、due队列、complete复测确认、history。
`/planner`提供预算/候选/草案/正式计划；`/reviews`提供队列与结果提交。首页显示当前计划和到期复习入口，工作台链接任务调整及复习安排。
