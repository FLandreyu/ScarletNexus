# P2草案与发布设计补全

## V1/V2合同与实际Schema执行

V1合同保持不变，AI生成仍请求V1供应商子集。合并或拆分升级当前草案为V2，增加mappings：操作ID、MERGE/SPLIT、MANUAL_DRAFT来源、原节点快照、目标ID及此前受影响关系。它是用户编辑记录，不是模型事实或能力证据。

GraphValidator先使用固定classpath合同执行JSON Schema 2020-12，再执行严格Java类型、所有权、分类树/全用户先修DAG规则。只允许V1/V2内置合同，不接受用户Schema或外部引用。新增com.networknt:json-schema-validator:1.5.9，依据[对应版本官方文档](https://github.com/networknt/json-schema-validator/tree/1.5.9)，兼容现有Jackson2；不引入YAML解析依赖。版本固定，升级须回归，未声称是最新版本或已完成全栈漏洞审计。

AI生成入口只接受所请求的V1候选；即使模型返回结构有效的V2，也不能伪造人工来源映射进入草案。V2由用户编辑转换产生。测试协议服务包含伪造V2响应，必须记录生成失败而不写候选或正式数据。

## 合并、拆分与撤销

转换只读取当前已保存草案，revision/状态不符409。合并保留目标UUID，源节点从当前技能候选中移出，子节点和关系转到目标，移除自环并合并重叠关系；若产生分类/先修环则拒绝。拆分产生2至8个新UUID，新节点沿用原描述/类型/状态/位置；子节点和原关系先连到第一个新节点，必须在预览中审核，可通过表单继续调整。

原节点定义不删除，已存在证据不自动迁移，快照保留源内容。草案最多100次映射，单份JSON最多1M字符、500节点/1500关系。来源映射与JSON一起撤销重做、保存，并随不可变发布版本持久化。链式转换的中间目标可能已移出当前草案，页面明确显示，而不是伪称当前仍有引用。

编辑器提供节点名称/描述/类型/归档、父节点与顺序、移出节点、关系增删改、合并/拆分表单。应用本地编辑后须保存，转换操作本身已保存且可撤销再保存。移出时提升子节点并移除该草案内相关关系，正式定义和历史保留；所有结果仍经过发布预览/确认。

## 联合发布

默认保留单技能保护：共享定义/关系会改变其他已发布技能时拒绝。用户选择includeAffectedSkills后重新预览，再确认发布，才允许联合发布。锁定用户行，记录其他已发布技能的规范化图谱快照；应用主草案后，仅给实际变化的其他技能追加版本及JOINT_PUBLISHED审计，关联根草案/版本。所有正式变更、快照、幂等键、审计同事务，任何一处失败全部回滚。

无变化技能不追加空版本；其他未发布草案不被覆盖，源指纹变化后发布会409。映射留在主V2版本中，其他技能新版本通过审计关联主发布，旧版本及原映射保持不变。

## 重复与来源提示

预览按NFKC、首尾/连续空白和大小写检测重复名称，列出候选ID，提示用户审核后合并；不自动合并，也不冒充语义去重。草案API返回创建/更新时间及MANUAL、AI_ASSISTED、AI_BASE、JOINT_PUBLISHED来源，历史版本返回发布时间。AI_BASE表示任务尚未成功产出候选，不伪称AI生成成功。

## V7显式有限修复

ai_generation_inputs保存当前用户提交给模型的主题及修复上下文、root/parent任务和depth；不会返回到公共任务API或打印日志，按owner隔离。此为恢复需要的私有业务数据，API Key不在该表。历史V5/V6任务不补造原主题，没有请求记录时不能使用服务器修复。

POST /api/v1/ai/jobs/{id}/repair要求会话/CSRF、Idempotency-Key和confirmed=true。只允许AI_INVALID_GRAPH、AI_INVALID_OUTPUT、AI_INCOMPLETE_OUTPUT，最多两次；每个父任务最多一个子任务，用户行锁和唯一约束防止分支/并发重复调用。重复请求返回已有子任务。认证、拒绝、网络超时、计费不明中断不自动重发。

每次修复都是新任务、新草案和独立预算预留，提示模型修正已知错误，原任务/草案/已发布版本不覆盖。新模型输出仍走完整校验。主题加上下文后超过50K字符时拒绝，不静默截断。失败可继续手动编辑原草案，不释放不确定费用。修复需要再次确认可能费用，默认生成关闭时不可调用。

V7只新增请求关联表，不修改V1–V6迁移或既有任务。流式导师/图像教学属于P4，生产预算硬限额和供应商账单对账不冒充P2的配置费率计算。
