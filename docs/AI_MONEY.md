# AI货币预算与价格快照

V6增加ai_money_days和ai_job_costs。任务创建、token预留、货币预留和价格快照在同一事务内，货币预算不足则整笔回滚，不发送请求。结算与任务状态/候选草案同事务；恢复中断任务时按预留金额保守计入UNKNOWN。用户行锁串行化预留和结算；重复结算不重复收费。

## 服务端配置

默认`app.ai.budget.enabled=false`，不为历史任务伪造成本记录。实际启用`app.ai.enabled=true`时必须同时配置货币策略，否则启动失败；重试必须为0，直到实现逐次调用计费。配置仅由服务器注入，不接受浏览器费率或预算。

| app.ai.budget 配置项 | 含义 |
| --- | --- |
| enabled | 是否启用货币账本 |
| currency | 三位大写币种代码，账本按币种隔离，不做汇率换算 |
| provider-label | 可公开供应商标识，不能填Key或带凭据URL |
| price-version / price-date | 价格配置版本及ISO日期，必填 |
| input-per-million / output-per-million | 每百万输入/输出token的配置费率，非负、小数最多12位 |
| per-job-reserve | 单任务预留金额，必须大于0 |
| daily-limit | 每用户每UTC日限额，不小于单次预留 |

还需配置`app.ai.model`，作为价格快照中的受控模型名。金额最多8位小数，费率和每日额度有合理数值上限，非法策略拒绝启动。环境变量按Spring命名规则，例如APP_AI_BUDGET_DAILY_LIMIT；当前Compose不转发这些变量，不提供真实价格或Key示例。

每个任务保存当时的provider/model/currency、price-version/date和输入输出费率。后续改价不重算旧任务；计费使用任务快照，而不是进程当前配置。

## 结算含义

`(inputTokens × inputRate + outputTokens × outputRate) / 1000000`使用BigDecimal计算，向上取至8位小数。完整非负用量按配置费率计算，source=PRICED_USAGE；它是配置价格下的计算值，不是供应商最终账单，不自动计入税费、缓存折扣或其他能力费用。

缺失用量/超时/中断时按预留金额记UNKNOWN；明确未配置、没有发送的请求记NOT_SENT、金额0。实际计算金额超过预留仍如实记账并阻止后续预算不足的预留；当前没有供应商侧硬支出上限，不能声称保证不超支。未知用量可能高于预留，对账仍需后续完成。重试关闭以避免只返回最后一次用量却漏计先前请求。

GET `/api/v1/ai/jobs/{id}/cost`只返回本人任务的费用快照；无历史记录为`{cost:null}`，不是费用为零；其他用户/未知任务404。密钥与prompt不进入费用响应。此轮无费用编辑页或生成创建API。

## 验证与剩余工作

测试价格均为本地测试数据，不引用或冒充实时供应商报价。真实PostgreSQL验证快照、精确计算、未知费用占用、重复结算、超预算回滚和所有权；单位测试验证舍入与配置约束。外部模型未调用。

仍需可信token策略与金额预留的估计依据、供应商逐次计费/证据对账、Schema兼容、生成入口和显式授权后的联调。当前仅结构化文本成本，流式、图片、工具费用不得直接套用这一费率模型。
