# 生成任务与token预算账本

P2内部应用服务`GenerationJobs`已实现同步编排；默认关闭的生成HTTP入口通过ConfiguredGeneration读取服务端策略，见AI_GENERATION.md。调用者必须是已认证用户；token日限额、单次预留和Provider不能直接透传用户请求。V6已接入可选货币账本和价格快照，见[AI_MONEY.md](AI_MONEY.md)。供应商联调仍需授权。

## 流程

1. 事务内锁用户行，以用户+幂等键查重。相同输入返回已有任务，输入变化拒绝；不存在才按UTC日期原子预留token。
2. 事务内创建独立草案、RUNNING任务和审计记录，正式图谱不变。V7为有限修复保留用户主题及修复上下文（私有业务表，按owner隔离），另存SHA256校验幂等；不打印到日志，不在公共任务API返回主题，不存API Key。旧任务不补造原主题。
3. 暂停外层事务，在所有数据库事务之外调用Provider。
4. 事务内校验返回结构/图规则，只有合法候选才保存到预先创建的草案。草案已被编辑则记录冲突，不覆盖用户修改；正式发布仍需现有预览和确认。
5. 任务状态、预算结算、草案变更和审计在同一事务完成。

V5新增ai_generation_jobs、ai_daily_budgets；任务和草案使用复合所有权外键。UTC日期在预留时确定，跨午夜的结算仍记原账本日期。用户行锁防止并发超额预留和重复调用。

## 预算含义与失败

这是token配额，不是货币费用：调用前预留可信策略给出的数额；供应商完整返回非负用量时按实际值结算。实际值超过预留仍如实记账，可能超出日配额并阻止后续请求；当前不能声称预算绝不超额或具有货币支出硬上限。用量未知、超时或断连按预留数额保守占用，usage_source为UNKNOWN；不假设上游未计费。明确AI_NOT_CONFIGURED记NOT_SENT并释放预留。非法候选也按可知用量结算，不以生成失败冒充免费。

任务RUNNING/SUCCEEDED/FAILED可读取，已完成任务不自动重发。同键的RUNNING任务返回已有状态，不重复消费。进程崩溃/落库失败保留RUNNING和预留；用户可在任务创建超过五分钟后确认结束：事务内记FAILED/AI_INTERRUPTED_UNKNOWN，预留转为UNKNOWN消耗，草案不变。重复操作不重复结算；迟到的Provider结果被忽略，不覆盖草案，也不自动以迟到用量调整账本。此操作不取消上游调用，不证明供应商已停止收费。没有自动释放、自动重试、后台线程或任务队列。

## 状态与恢复入口

登录后导航“生成任务”进入`/ai/jobs`，按每页20项查看状态、时间、错误码和token记录，链接至相关技能草案；无任务时显示真实空状态。RUNNING且超过五分钟时显示确认结束选项。状态刷新为手动刷新，不增加后台轮询。

- GET `/api/v1/ai/jobs?page=0&size=20`：当前用户列表，size 1–100，page 0–10000。
- GET `/api/v1/ai/jobs/{id}`：当前用户任务，不存在或其他用户返回404。
- POST `/api/v1/ai/jobs/{id}/recover`：JSON `{confirmed:true}`，要求会话/CSRF；未确认422，仍活跃409，已结束幂等返回当前状态。

响应不包含完整prompt、密钥、输入hash或幂等键。创建时间与五分钟阈值由数据库判断；这是一项用户确认的保守结束操作，不是断言某个进程已崩溃。默认关闭的生成入口见AI_GENERATION.md。

V7新增显式修复：POST `/api/v1/ai/jobs/{id}/repair`，须确认与幂等键，仅针对已知结构/截断错误，最多两次、每父任务唯一子任务。各自新任务、草案和预算，原记录保留；无请求主题的旧任务不补造输入。来源字段repairDepth/parentJobId可追溯，主题不出现在任务响应。详见P2_DESIGN.md。

token估计、固定Schema执行、生成入口和有限修复已实现；剩余真实供应商/质量验收需要授权和本地Key配置。供应商账单对账、更多筛选和生产安全后续复核，不直接公开内部generate方法或接受客户端传模型费率。
